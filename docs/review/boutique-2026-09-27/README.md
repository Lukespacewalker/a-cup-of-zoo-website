## ขอบเขตและแผนปัจจุบัน

ผู้ใช้อนุมัติให้ปรับเว็บเดิมเป็นน่ารักแบบ boutique: คงครีม เขียวมะกอก น้ำตาล โลโก้ ตัวสัตว์ และภาพจริง ลดภาพเอียง เทป กรอบโพลารอยด์ และของตกแต่งที่ซ้อนกัน จัดภาพหลัก/รอง ปรับตัวอักษรไทยและระยะห่าง ให้ดูเมนูและวางแผนเที่ยวได้ง่าย

แผน: (1) ตรวจเอกสาร/source/เว็บเดิม (2) ปรับองค์ประกอบร่วมและหน้าแรก (3) ตรวจ render และ interaction ทุกหน้าหลัก (4) ตรวจ source โดยผู้ตรวจแยกคนและบันทึกผล ทั้งหมดทำใน working tree เดิม ไม่แก้ CMS หรือ deploy

เกณฑ์รับงาน: ภาพหลักเด่น ภาพรองตรงแนว ความน่ารักยังอยู่ ตัวไทยอ่านได้บนมือถือ เมนู/ทางมาเที่ยวเห็นง่าย ไม่มีแนวนอนล้น ใช้ navigation/theme/ลิงก์หมวด/ภาพเพิ่มเติมได้ รักษาข้อมูลและ noindex เดิม

ขณะเริ่มงาน Git สะอาด HEAD `efe43da` ซึ่งรวมงานเมนูและ SEO แล้ว แม้ handoff อ้างสถานะก่อน commit จึงทำต่อจาก HEAD ที่พบจริง ไม่มีการย้อนงานเดิม

## สิ่งที่เปลี่ยน

- หน้าแรก: ภาพสัตว์หลักหนึ่งภาพ ภาพสวนและเครื่องดื่มรองตรงแนว ตัดกรอบ เทป และ doodle ที่ทับภาพบน hero; คงโลโก้, fox seal, เป็ด และภาพจริงเดิม
- ข้อกำหนดเพิ่มเติมระหว่างตรวจ: ผู้ใช้ต้องการ doodle สัตว์น่ารักให้เห็นชัด การลดหมายถึงลดความรก ไม่ใช่เอาความน่ารักออก จึงแทน sprig ด้วยแมวลายเส้นข้างหัวเรื่อง (มือถืออยู่ก่อนหัวเรื่อง) และกระต่ายข้างหัวเรื่องช่วงสวน ใช้ doodle เดิมสีตามธีมในพื้นที่ของตัวเอง ดูภาพแยก `garden-doodles-390.png` / `garden-doodles-1440.png`
- หัวเรื่องใช้ Noto Sans Thai Looped; Mali เหลือใน caption/ข้อความสั้น ปรับขนาด ระยะบรรทัด และช่องว่างของส่วนต่าง ๆ พื้นครีมเรียบกับช่วงสีมะกอก
- เพิ่มดูเมนูอาหาร/วางแผนมาเที่ยวใกล้หัวเรื่อง ทำปุ่มมาเที่ยวใน header ให้เด่น และใช้แถบทางลัดสองปุ่มที่ขอบล่างมือถือ แทนปุ่มลอยทับเนื้อหาอย่างไม่มีพื้นแยก
- ลดทางซ้ำที่ชี้หน้าเมนูเดียวกันใต้ชื่อเครื่องดื่ม/ขนม ไม่เพิ่มเมนูหรือราคาที่ผู้ใช้ยังไม่มี; catalog ทั้ง 47 รายการยังอ่านใน HTML ได้โดยไม่ใช้ JavaScript
- Playwright อนุญาต reuse server เฉพาะเมื่อผู้รันตั้ง `PLAYWRIGHT_REUSE_SERVER=1` ค่าเริ่มต้นยังเปิด server แยกตามเดิม

ไม่เปลี่ยน catalog, ภาพอาหารต้นฉบับ 20 ภาพ, ราคา/ตัวเลือก/ท็อปปิง, แพ็กเกจ/เงื่อนไขเด็ก, สองเบอร์ใน contact.ts, Maps, metadata/JSON-LD หรือ noindex

## ผู้ตรวจและเป้าหมาย

Root เป็นผู้ทำและตรวจเว็บ/ภาพเอง ผู้ตรวจแยกคนได้รับ brief และไฟล์เป้าหมายโดยไม่รับประวัติการทำงาน ใช้ workspace ร่วมแบบอ่านอย่างเดียว ไม่แก้ product/tests และไม่เปิด server เพิ่ม ภาพและผล interaction เป็นหลักฐานที่ Root สร้าง ไม่อ้างว่า reviewer ทำ interaction เอง

เป้าหมายเป็น HEAD บวก dirty/untracked delta ระบุ SHA-256 ใน `review-target.json` รวม product, tests, catalog/contact/SEO และภาพอาหาร/ภาพตรวจหน้าจอ เพื่อระบุสิ่งที่ได้รับการตรวจแน่นอน

สถานะรับงาน: **PASS สำหรับธีมและการใช้งานในเครื่อง** ยังไม่ได้ deploy

รอบก่อนข้อกำหนด doodle เพิ่ม ผู้ตรวจให้ PASS ตรวจ hash 66 ไฟล์ตรง รัน E2E เอง 18/18 ผ่าน และทดสอบ Tab 45 จุดแรกของหน้าเมนูที่ 390×900 โดยไม่พบ focus ถูกแถบทางลัดบัง หลังเพิ่มแมว/กระต่าย Root เก็บภาพใหม่และรัน E2E 18/18 กับ check (40 ไฟล์ ไม่มี diagnostics) ผ่าน

ผู้ตรวจทบทวน delta ล่าสุดให้ **PASS** ตรวจ hash ล่าสุดทั้ง 66 ไฟล์ตรง ดูภาพ cover/full home 8 ภาพ (390/1440 light/dark) และใช้เว็บจริงตรวจการทับกันที่ 320/390/560/768/860/1000/1440 px ไม่พบกระต่ายทับข้อความ ภาพ หรือปุ่ม และไม่มีแนวนอนล้น ตรวจขอบเขต glyph ของหัวเรื่องที่ 861/900/1000/1200/1440 px ไม่พบแมวทับตัวอักษร แม้กรอบ block ของหัวเรื่องมีพื้นที่ว่างกว้าง ไม่พบข้อค้างบังคับแก้

Root รัน build ชุดสุดท้ายผ่านโดยหยุด dev server ก่อน prepare-assets แล้วเปิด server กลับให้ตรวจเว็บได้ Unit/content checks ใช้หลักฐานรอบนี้ก่อนเพิ่ม doodle ซึ่งไม่แตะข้อมูลหรือ logic ที่ตรวจแล้ว; source/ภาพต้นฉบับไม่เปลี่ยน และ git diff --check ผ่าน
