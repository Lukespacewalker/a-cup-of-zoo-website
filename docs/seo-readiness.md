# SEO readiness — 26 กันยายน 2026

> 27 กันยายน: เพิ่ม html lang, canonical/hreflang/OG และ sitemap สำหรับหน้าคู่ TH/EN แล้ว Local/staging ยัง noindex ดู [ขอบเขตและผลตรวจล่าสุด](review/th-en-2026-09-27/README.md) ส่วนผลทดสอบด้านล่างเป็นประวัติรอบ SEO ก่อนเพิ่มภาษาอังกฤษ

เว็บไซต์ยังอยู่ระหว่างเตรียมงาน ผู้ใช้ยืนยันให้คง `noindex` ไว้ รอบนี้ปรับ SEO ในโค้ดและสรุปข้อเสนอธีม ยังไม่ได้ deploy การเปลี่ยนแปลงชุดนี้

> อัปเดตต่อเนื่อง 26 กันยายน: นำเข้าเมนูอาหาร 47 รายการและกิจกรรมเป็นหน้าเว็บแล้ว เพิ่ม Menu JSON-LD พร้อมราคาที่ตรงกับหน้าเว็บ และ hasMap ของร้าน ผู้ใช้เลือกแสดงทั้งสองเบอร์ อ้างอิงข้อมูล เวลาเปิด และข้อยกเว้นจากหลักฐานใหม่ ดู [ขอบเขตและผลตรวจล่าสุด](menu-import.md) ข้อความรอเติมค่าเข้า/กิจกรรมและความขัดแย้งเบอร์ด้านล่างเป็นสถานะก่อนนำเข้า ไม่ใช่งานค้างปัจจุบัน

## ส่วนที่ปรับแล้ว

- Title และ meta description ของ 6 หน้าหลักสื่อถึงเนื้อหาของแต่ละหน้าและทำเลคลอง 6 ปทุมธานี โดยคงข้อความที่มองเห็นและธีมเดิม
- Open Graph และ Twitter Card ใช้ชื่อ/คำอธิบายของหน้าที่แชร์ ภาพแมวกับสุนัขจากร้านแปลงเป็น JPEG พร้อมขนาดภาพและคำอธิบายภาพ URL แชร์ตัด query สำหรับติดตามออก
- `CafeOrCoffeeShop` ใช้ชื่อวันตามรูปแบบที่ Google รองรับ ไม่ส่งวันปิดหรือเวลาที่ไม่ครบ และคงเงื่อนไขว่าข้อมูลเวลาต้องผ่านการตรวจสอบ เพิ่มภาพ เพจ Facebook และลิงก์เว็บไซต์/เมนูเมื่อมีโดเมน production
- Canonical, sitemap, robots และตัวระบุร้านอ่านโดเมนจาก `site` ใน `astro.config.mjs` จุดเดียว Sitemap ใน production จะตอบ 503 หากยังใช้ `.invalid` แทนการส่ง URL ตัวอย่างออกไป
- Local/staging ยังมีทั้ง meta robots และ `X-Robots-Tag: noindex, nofollow`, robots.txt เป็น `Disallow: /` และ sitemap ว่าง ภาพแชร์ของ preview จึงยังไม่ได้รับรองว่าจะถูกดึงมาแสดงโดยทุกแพลตฟอร์ม

## สิ่งที่ต้องทำก่อนเปิดจริง

1. ยืนยันชื่อร้าน เบอร์หลัก เวลาเปิด วันหยุด และข้อมูลที่จอดรถกับเจ้าของร้าน ให้ข้อมูลบนเว็บ CMS และ Google Business Profile ตรงกัน ข้อมูลปัจจุบันยังมีเบอร์จาก Facebook กับ Google Maps ต่างกัน และหลักฐานใน `reference-data/business-evidence.json` ยังมีรายการรอยืนยัน
2. ยืนยันโดเมนจริง แล้วเปลี่ยน `site` ใน `astro.config.mjs` เชื่อม CMS production ที่เข้าถึงได้จาก Cloudflare โดยไม่เปลี่ยน preview ให้ index ไปด้วย
3. ตรวจบน production: หน้าเนื้อหาตอบ 200, หน้าที่ไม่มีตอบ 404, canonical ชี้โดเมนจริง, sitemap เปิดได้ และข้อมูล JSON-LD ตรงกับข้อมูลที่ผู้ใช้เห็น ตรวจด้วย Rich Results Test และ URL Inspection
4. ตั้ง Google Search Console และส่ง sitemap เมื่อเว็บพร้อม ตรวจข้อมูล Google Business Profile ทั้งหมวดธุรกิจ หมุดแผนที่ เวลาเปิด รูป และลิงก์เว็บไซต์
5. วัด PageSpeed/Core Web Vitals บนมือถือก่อนปรับความเร็ว เป้าหมาย LCP ≤ 2.5 วินาที, INP ≤ 200 ms และ CLS ≤ 0.1 รอบนี้ยังไม่ได้วัดคะแนนหรือข้อมูลผู้ใช้งานจริง จุดที่ควรตรวจคือขนาดภาพ hero, การเลือกภาพจาก srcset, น้ำหนักฟอนต์ และ cache ของ HTML
6. เติมเนื้อหาที่ช่วยตัดสินใจมาเที่ยว: ค่าใช้จ่ายจริง เงื่อนไขกิจกรรม ข้อควรปฏิบัติกับสัตว์ เส้นทาง และที่จอดรถ ใช้คำค้น “คาเฟ่สัตว์ คลอง 6” และ “คาเฟ่ ปทุมธานี” อย่างเป็นธรรมชาติ คำเหล่านี้เป็นข้อเสนอจากลักษณะร้าน ยังไม่ได้วิจัยปริมาณค้นหา

วัดผลด้วยคำค้นและยอดคลิกจาก Search Console รวมถึงการกดดูเส้นทางและติดต่อร้าน การมี metadata หรือ structured data ไม่ใช่หลักฐานว่าอันดับดีขึ้น

## ข้อเสนอธีมสำหรับรอบถัดไป

> 27 กันยายน: ผู้ใช้อนุมัติแนว boutique และลงมือปรับแล้ว ข้อเสนอ/ข้อจำกัดการจับภาพในส่วนนี้เป็นประวัติของรอบก่อน ดู [การเปลี่ยนแปลงและหลักฐานธีมล่าสุด](review/boutique-2026-09-27/README.md) สำหรับสถานะปัจจุบัน

ความเห็นจากภาพ review ในโปรเจกต์และสไตล์ปัจจุบัน: เว็บไซต์สื่อความน่ารักและความอบอุ่นชัด ส่วน luxury ยังรองลงมา โทนครีม เขียวมะกอก และน้ำตาลมีพื้นฐานที่ดีสำหรับแนว boutique

- เก็บโลโก้สัตว์ โทนครีม ภาพจริง และน้ำเสียงเป็นกันเอง
- ลดจำนวนภาพเอียง กรอบแบบโพลารอยด์ เทป และ doodle ในจุดเดียวกัน เลือกของตกแต่งเด่นเพียงหนึ่งชิ้นต่อช่วงเนื้อหา
- ให้ภาพหลักเด่นหนึ่งภาพ แล้วใช้ภาพรองที่มีขนาดและแนวจัดวางสม่ำเสมอขึ้น ใช้ภาพจากร้านที่มีแสงและโทนไปทางเดียวกัน โดยรักษาสิทธิและข้อมูลในภาพต้นฉบับ
- ทดลองหัวเรื่องที่นิ่งและประณีตขึ้น โดยเก็บฟอนต์ลายมือไว้เฉพาะข้อความสั้น ๆ ประเมินการตัดบรรทัดภาษาไทยบนมือถือควบคู่กัน
- ทำลิงก์ “ดูเมนู” และ “วางแผนมาเที่ยว” ให้เห็นง่าย ความหรูควรมาจากการจัดภาพและลำดับข้อมูลที่ชัด

รอบนี้ไม่ได้เปลี่ยนธีมหรือประเมินภาพใหม่ครบทุกขนาด การจับภาพ preview ผ่าน BrowserOS timeout; ใช้ภาพ review ที่บันทึกไว้ร่วมกับ source ปัจจุบันประกอบข้อเสนอ จึงไม่ใช่การรับรอง visual acceptance ของ production

## การตรวจรอบนี้

- Unit tests 12 รายการผ่าน รวมชื่อวัน ข้อมูลเวลาไม่ครบ โดเมนตัวอย่าง และ XML ของ sitemap
- E2E ทั้งชุด 12 รายการผ่าน หลังเพิ่มการตรวจ URL แชร์ที่มี query และขนาดภาพ ได้รันชุด SEO ที่ได้รับผลกระทบซ้ำอีก 6 รายการและผ่านทั้งหมด
- `bun run check`: 0 errors, 0 warnings, 0 hints; `bun run build` และ `git diff --check` ผ่าน
- `bun run verify:content` ไม่พบข้อมูลผิดรูปแบบ แต่ยังมีรายการธุรกิจรอยืนยันตามที่ระบุด้านบน
- เป็นการตรวจโดย Root ใน workspace เดียวกัน การทดสอบเว็บใช้ข้อมูล fixture ในเครื่อง ไม่ใช่การทดสอบ production หรือการยืนยันอันดับค้นหา
