# สัตว์และระบบโหวตผ่าน CMS

รูปสัตว์ทั้งการ์ด โหล และ podium ใช้จุดโฟกัสเดียวกันจาก CMS (`imageFocus`: ตำแหน่ง x/y 0–100 และซูม 1–4) แก้และดูตัวอย่างได้ในหน้าแก้สัตว์ หรือส่งผ่าน MCP `update_animal_draft` แล้วเผยแพร่ตามขั้นตอนเดิม เมื่อเปลี่ยนรูป จุดโฟกัสเดิมจะถูกล้าง เว้นแต่ระบุจุดโฟกัสใหม่พร้อมกัน รูปเก่าที่ไม่มีค่านี้ยังแสดงแบบครอปกลางภาพ กรอบของมีโชคอ้างอิงภาพต้นฉบับเต็ม เนื่องจากไฟล์ที่แยกก่อนหน้าตัดจมูกออกบางส่วน ดู [แผนและเกณฑ์ตรวจ](superpowers/plans/2026-10-29-animal-faces.md)

สีบอลใช้ลำดับคะแนนสะสมเป็นตัวกำหนด ลูกที่กำลังตกและลูกในโหลจึงใช้สีเดียวกัน รวมถึงหลังโหลดใหม่และเมื่อขึ้นโหลใหม่ทุก 50 คะแนน ใช้ชุดสีเดียวกันทั้ง HTML จากเซิร์ฟเวอร์และการโหวตในเบราว์เซอร์ การแก้นี้ไม่เปลี่ยนข้อมูลหรือ API ของ CMS ตรวจการโหวตซ้ำและสีช่วง 49 → 50 → 51 คะแนนในชุดทดสอบ CMS แบบแยกข้อมูลแล้ว ติดตาม deployment ล่าสุดได้ที่ [GitHub Actions](https://github.com/Lukespacewalker/a-cup-of-zoo-website/actions)

ประวัติหน้าตา: รุ่น `d99b1af6-25b6-45b3-8dfd-fd189c5afb30` เพิ่มแท่น Three.js ทั้งหน้าแรกและหน้าสัตว์ ย้ายรูปวงกลมมาแปะบนโหล แสดงโหลเต็มเป็นรูปโหลเล็ก × จำนวนแทนข้อความคำนวณ และย้ายโหลดคะแนนขึ้นด้านบน การ์ด/ปุ่มใช้ขอบตรง คะแนนเดิมใน CMS อยู่ครบ ดู [หลักฐานรอบนี้](review/animal-podium-2026-10-28/README.md) รุ่นและคำอธิบายหน้าตาด้านล่างเป็นประวัติที่รอบนี้แทนที่แล้ว

รุ่นล่าสุด: รวมหน้าแนะนำสัตว์และโหวตแล้วที่ [สัตว์และโหวต](https://acupofzoo.com/animals/) และ [English](https://acupofzoo.com/en/animals/) เวอร์ชัน `6a9de7ed-da00-422b-863c-f867f3221ac9` ลิงก์ /vote/ เดิมเปลี่ยนทางให้อัตโนมัติ ลูกบอลใช้จำนวนจริง 1 คะแนน = 1 ลูก ครบ 50 ลูกเก็บเป็นโหลเต็ม ชื่อ รูป และคะแนนของสัตว์ทั้ง 23 ตัวคงเดิม ดู [หลักฐานรุ่นล่าสุด](review/unified-animals-2026-10-28/README.md)

**ประวัติรุ่นแรกด้านล่าง:** รุ่นล่าสุดด้านบนแทนที่หน้าโหวตแยกและการแสดงลูกบอลแบบสัดส่วน ส่วน CMS/MCP ยังใช้ระบบเดิม

สถานะ 28 ตุลาคม 2026: **deploy และตรวจเว็บจริงแล้ว** ที่ [หน้าโหวต](https://acupofzoo.com/vote/) และ [ภาษาอังกฤษ](https://acupofzoo.com/en/vote/) เว็บไซต์เวอร์ชัน `4b18293c-4c0b-486a-860e-dfec07ca78c7` อ่านข้อมูลจาก CMS จริง มีสัตว์ Canva ครบ 23 ตัว รูปครบ และรวมงาน ZooClub ที่ผ่านการตรวจแล้ว ดู [หลักฐาน deployment](review/animal-voting-2026-10-28/deployment.md)

CMS Admin อยู่ที่ [จัดการสัตว์](https://acupofzoo-cms-admin.a-cup-of-zoo-website.workers.dev/th/animals) และ MCP อยู่ที่ `https://acupofzoo-cms-api.a-cup-of-zoo-website.workers.dev/mcp` ใช้สิทธิ์แยกของร้าน การตั้งค่า Codex/Claude บน MacBook และงาน Listing ติดตามใน [แชท CMS และบันทึกส่งต่อ](cms-cloudflare-deployment-2026-10-28.md)

หลังขึ้นจริง ตรวจ 17 เส้นทางทั้ง apex/www รวม 34 คำตอบ HTTP 200, หน้าไทย/อังกฤษ รูปสัตว์ครบ 23 ภาพ, มือถือ 320/390px และลิงก์จากแท่นหน้าแรกเข้าโหลคะแนน ทดสอบกดโหวตให้นามะจริงสองครั้ง (0 → 1 → 2) และยืนยันคะแนนคงอยู่หลังโหลดใหม่ทั้งสองโดเมน เก็บสองคะแนนนี้ไว้ ไม่รีเซ็ตข้อมูล production

## สิ่งที่จัดการได้

CMS มีหน้า `/th/animals` และ `/en/animals` สำหรับเพิ่มสัตว์ แก้ชื่อ/คำบรรยายไทย–อังกฤษ อัปโหลดหรือเลือกรูป ซ่อน/เปิด และเรียงลำดับ รองรับสูงสุด 100 รายการตาม schema ปัจจุบัน การเพิ่มหรือแก้สัตว์ไม่ต้องแก้โค้ดเว็บไซต์

บันทึกเป็นฉบับร่างก่อน แล้วกดเผยแพร่เฉพาะรายชื่อสัตว์ ข้อมูลร้านส่วนอื่นที่ยังเป็นฉบับร่างจะไม่ถูกเผยแพร่ตามไปด้วย ทุกตัวมี ID คงเดิมเมื่อเปลี่ยนชื่อหรือรูป การซ่อนแล้วเปิดกลับมาไม่ล้างคะแนน ไม่มีปุ่มลบถาวรหรือรีเซ็ตคะแนน

MCP ใช้ `list_animals`, `create_animal_draft`, `update_animal_draft`, `reorder_animal_drafts` และ `publish_animals` ทุกคำสั่งใช้กฎเดียวกับหน้า Admin และตรวจเวอร์ชันก่อนเขียน ดูรายละเอียดใน [CMS MCP catalog](../../CMS-Platform-acupofzoo/docs/mcp.md)

## รายชื่อจาก Canva

เทียบ [Canva หน้า 4](https://www.canva.com/design/DAHYz2902Do/uNqLI2aFUF5ZNF389Mwscg/view#4) กับไฟล์ที่เก็บไว้แล้ว รวม **23 ตัว**:

- จิ้งจอก 5: นามะ, ไดฟุกุ, โดรายากิ, โมจิ, เซมเบ้
- เมียร์แคต 4: มีตังค์, มีทอง, มีโชค, มีเฮง — แยกเป็นรายตัว
- สุนัข 11: ไข่เจียว, ไข่ดาว, แคนดี้, มายด์ (MINE), หยินหยาง (YIN-YANG), หมูกรอบ, ไข่เยี่ยวม้า, หนำเลี๊ยบ, ข้าวเจ้า, ลูกชิ้น, ไส้กรอก
- แมว 3: ทาร์ต, สำลี, เวเรส

เจ้าของยืนยันว่าภาพชื่อ MINE ที่ซ้ำเป็นตัวเดียวกัน และ YIN-YANG ที่ซ้ำเป็นตัวเดียวกัน จึงมีอย่างละหนึ่ง ID และหนึ่งคะแนนสะสม เก็บเลขการ์ดต้นทางทั้งคู่ใน [ข้อมูลรายชื่อ](../reference-data/owner-feedback-2026-10-27/animal-roster.json)

ดาวน์โหลดภาพรวมสุนัข/แมวขนาด 1599 × 601 เพิ่มจาก Canva เพื่ออ่านรายละเอียด แล้วแยกภาพรายตัวจากแผ่นต้นทาง โดยเก็บต้นฉบับและ [พิกัด/ค่าแฮชภาพ](../reference-data/owner-feedback-2026-10-27/animal-assets-manifest.json) ไว้ ภาพสุนัข/แมวรายตัวมีความละเอียดตามต้นทาง ไม่ได้สร้างหรือขยายรายละเอียดด้วย AI

นำเข้า **23 รายการเป็นฉบับร่างใน CMS ที่เครื่อง** แล้ว (`CMS-Platform-acupofzoo/apps/api/.local-cms-acupofzoo/cms.sqlite`, เวอร์ชัน 33) รักษา 3 รายการเดิมและฉบับเผยแพร่ไว้ครบ จึงมี draft รวม 26 รายการ รายการเดิมเป็นแมว, แมวและสุนัข, เป็ด ยังไม่ได้รวม/ซ่อนอัตโนมัติ มีสำรองฐานข้อมูลก่อนนำเข้าที่ `C:/Users/Sutti/AppData/Local/Temp/acupofzoo-before-roster-20261028`

`scripts/import-cms-animals.ts` เป็นเครื่องมือนำเข้าครั้งแรกเท่านั้น: จำกัด localhost และ project `acupofzoo`, ปฏิเสธ redirect, ค่าเริ่มต้นเป็น dry run, `--apply` เพิ่มฉบับร่างที่ยังไม่มี และไม่ทับข้อมูลที่มีอยู่ ไม่เผยแพร่เอง ตรวจรันซ้ำแล้วไม่สร้างซ้ำ งานแก้ประจำวันทำใน CMS/MCP

## ประวัติการโหวตและหน้าเว็บรุ่นแรก (แทนที่แล้ว)

หน้าแรกมีแท่นอันดับสามตัวพร้อมลิงก์ไป `/vote/` หรือ `/en/vote/` หน้ารายละเอียดแสดงรูป โหล ลูกบอล ตัวเลขคะแนน และปุ่มโหวต ไม่ต้องสมัครสมาชิกและกดซ้ำได้ คะแนนเพิ่มทีละหนึ่งจากคำตอบของ CMS จริง

ตัวเลขเป็นคะแนนจริง ส่วนลูกบอลแสดงสัดส่วนและจำกัดไม่เกิน 45 ลูกต่อโหลเพื่อไม่ให้หน้าเว็บหนัก มีข้อความยืนยันใกล้ปุ่ม รองรับคะแนนศูนย์ อันดับเสมอ ไม่มีสัตว์ และ CMS ขัดข้อง รวมถึงจอมือถือและ reduced motion

คะแนนอยู่ในตาราง `animal_vote_counts` แยกจากข้อมูลสัตว์และเวอร์ชันฉบับร่าง ใช้ migration เพิ่มใหม่ `0012_acupofzoo_animal_votes.sql` การตรวจสิทธิ์รับคะแนนกับการเพิ่มคะแนน/audit อยู่ในธุรกรรมเดียวกัน เปิดโมดูลนี้เฉพาะ `acupofzoo` การโหวตจึงไม่แก้เนื้อหาสัตว์หรือเพิ่มเวอร์ชันข้อมูลร้าน
