# งานที่ลงมือแก้จากบรีฟเจ้าของร้าน

**สถานะปัจจุบัน 28 ตุลาคม 2026:** CMS/สัตว์ 23 ตัว/โหวต/โหลคะแนนและ ZooClub ขึ้นเว็บจริงแล้ว เวอร์ชัน `4b18293c-4c0b-486a-860e-dfec07ca78c7` ดู [หลักฐานหลัง deploy](review/animal-voting-2026-10-28/deployment.md) ข้อความยังไม่ deploy/CMS ยังรอด้านล่างเป็นประวัติของรอบก่อน

**อัปเดต 28 ตุลาคม 2026 — สัตว์และโหวต (ยังไม่ deploy):** คำอธิบายด้านล่างว่าไม่มีฟอร์มสัตว์/ยังไม่เพิ่มสุนัขและแมว/โหวตรอดำเนินการ เป็นประวัติของรอบก่อนแล้ว รอบใหม่มี Admin และ MCP สำหรับสัตว์ พร้อมระบบโหวตและโหลคะแนน รวมรายชื่อ Canva ครบ23ตัวตามการยืนยันชื่อซ้ำของเจ้าของ ดู [สถานะและหลักฐานปัจจุบัน](cms-animal-voting.md) ข้อมูลนำเข้าเป็น draft ใน CMS ที่เครื่อง ส่วน CMS บนคลาวด์ยังรอเตรียม

อัปเดตล่าสุด: เผยแพร่ Footer พร้อมที่อยู่เต็ม เบอร์สองเบอร์ Facebook, Instagram และ TikTok รวมส่วนชวนติดตามหน้าแรกทั้งสองภาษาแล้ว เอา noindex ออกจากโดเมนหลักและ www เปิด robots และ sitemap15หน้า เวอร์ชัน `8556b10b-60bf-4578-9093-efc3477eae35` ผ่าน check/unit/build, browser checks, รีวิวอิสระ และตรวจเว็บจริง ดู [หลักฐานรอบนี้](review/footer-social-2026-10-27/README.md) CMS จริงยังรอเชื่อมต่อ และงานแผนที่ที่กำลังแก้พร้อมกันยังไม่รวมในการเผยแพร่รอบนี้

**ประวัติการเผยแพร่ก่อนหน้า** — สถานะ noindex ด้านล่างถูกแทนด้วยคำสั่งเปิด indexing ในรอบล่าสุด:

สถานะ: ผ่านการทดสอบและรีวิวอิสระ แล้วเผยแพร่หน้าเว็บตามคำอนุมัติ “เอาขึ้นได้เลย” เมื่อ 27 ตุลาคม 2026 บน [acupofzoo.com](https://acupofzoo.com/) และ [www.acupofzoo.com](https://www.acupofzoo.com/) เวอร์ชัน `063e6f63-2955-484d-aedd-094ba6194851` ส่วน CMS/MCP ยังไม่ได้เปิดบนคลาวด์

ตรวจหลัง deploy ผ่าน BrowserOS neo: 15 เส้นทางต่อปลายทาง รวมโดเมนหลัก www และ workers.dev เป็น 45 จุด ตอบ 200 พร้อมเนื้อหาที่คาดหมาย สลับภาษา Zoo Clubs ได้ ตรวจภาพกิจกรรม/สัตว์บนมือถือ โลโก้พาร์ตเนอร์ และเปิด/ปิดแผนผังด้วย Enter ได้ ไม่พบภาพเสียหรือหน้าเว็บล้นในขนาดที่ตรวจ เว็บยังใช้ `staging/fixture` และ `noindex` ตามเดิม ดู [หลักฐานการเผยแพร่](review/owner-ready-2026-10-27/deployment.json)

แหล่งข้อมูล: [บรีฟที่เก็บไว้](owner-feedback-2026-10-27.md) และ [แผนงานปัจจุบัน](superpowers/plans/2026-10-27-owner-ready-content.md)

## หน้าเว็บที่เพิ่มและแก้แล้ว

- **เมนู:** คงอาหาร HTML 47 รายการและราคา เพิ่มลิงก์เล่มอาหารกับเครื่องดื่มของเจ้าของร้าน เปิดเมื่อผู้ใช้กด ไม่มี iframe หรือการโหลด Heyzine อัตโนมัติ
- **กิจกรรม:** เพิ่ม Free Zone Pass พร้อมขั้นต่ำ 1 ออร์เดอร์/คน แสดงภาพแผนผังและเปิดขนาดใหญ่ให้เลื่อนดูได้ ใช้แป้นพิมพ์และใช้งานได้เมื่อปิด JavaScript
- **แผนผัง:** แสดงเฉพาะส่วนภาพก่อนกล่องเบอร์เก่าด้านล่าง โดยเก็บต้นฉบับไว้ครบ ใช้รายชื่อจุดใน HTML และข้อมูลติดต่อของเว็บแทน ข้อนี้แทนข้อเสนอเดิมที่ให้รอภาพแก้เบอร์ก่อนนำภาพเต็มมาใช้
- **สัตว์:** เพิ่มโปรไฟล์จิ้งจอก นามะ ไดฟุกุ โดรายากิ โมจิ เซมเบ้ และแก๊งเมียร์แคต มีตังค์ มีทอง มีโชค มีเฮง ชื่อสุนัข/แมวในภาพรวมมีชื่อซ้ำและตัวอักษรเล็ก จึงยังไม่สร้างโปรไฟล์รายตัวจากภาพนั้น
- **ทัวร์กลุ่มและร่วมงาน:** เพิ่ม `/events/` และ `/en/events/` พร้อมภาพทัวร์กลุ่ม Suzuki Demo Day และ Yagi Milk ใช้เบอร์ที่ตกลงไว้สำหรับสอบถามวัน จำนวนคน และรูปแบบงาน ไม่ใส่ราคาหรือจำนวนรองรับที่ยังไม่มีข้อมูล
- **Zoo Clubs:** เพิ่ม `/club/` และ `/en/club/` มีสมาชิก 5 ระดับ สิทธิ เงื่อนไข ของแลกแต้ม 7 รายการ ทางไป LINE `@acupofzoo` และโลโก้พาร์ตเนอร์ 6 ราย ไม่มีการจำลองยอดแต้ม/บัญชีสมาชิกหรือสิทธิของพาร์ตเนอร์ที่ยังไม่ระบุ
- เพิ่มทางเข้าจากหน้าแรก ท้ายหน้า และเมนูมือถือ พร้อมเส้นทางสลับภาษาและ SEO metadata ของหน้าใหม่ ใช้ภาพต้นฉบับจากบรีฟผ่านระบบภาพของ Astro

ลิงก์ LINE เปิดหน้า Add friend ได้ แต่ยังไม่ได้สมัครสมาชิก ส่งข้อความ หรือยืนยันการเชื่อม API แต้มกับ LINE

## CMS และ MCP

แก้ใน `../CMS-Platform-acupofzoo` ซึ่งใช้แพลตฟอร์มเดียวกับ Portfolio และมีโปรไฟล์ `acupofzoo` แยกข้อมูลอยู่แล้ว เพิ่ม `get_venue`, `save_venue_draft`, `publish_venue`, `update_post_draft` และ `upload_cafe_image` ผ่าน schema/use case เดิมของหลังบ้าน:

- AI อ่านฉบับปัจจุบันและเวอร์ชันก่อนแก้ บันทึกเป็นร่างโดยไม่กระทบฉบับที่เผยแพร่
- เผยแพร่เป็นคำสั่งแยก ตรวจเวอร์ชันเพื่อกันเขียนทับ และบันทึก audit เป็น `ai/mcp`
- ใช้ MCP token แยกจาก Admin; ไม่เพิ่มสิทธิให้ Portfolio หรือ Nuchaba เรียกเครื่องมือข้อมูลร้าน
- แก้รายชื่อโปรไฟล์ใน Vite ที่เคยทำให้ build Admin ของ A Cup of Zoo ล้มเหลว
- คู่มือการต่อ endpoint, token และลำดับคำสั่งอยู่ใน `../CMS-Platform-acupofzoo/docs/mcp.md`

**ขอบเขตตามที่ผู้ใช้ชี้แจง:** CMS/MCP ดูแลบทความ ข่าว รูป/รายชื่อสัตว์ เวลาเปิดปิด และข้อมูลติดต่อ ส่วนโค้ดดูแลโครงสร้าง เลย์เอาต์ และฟังก์ชันใหม่ เจ้าของจะเข้าถึงโค้ดเพื่อใช้ AI แก้ส่วนเหล่านั้นได้ ไม่ต้องทำ CMS ให้เปลี่ยนโครงสร้างเว็บ

หน้าโปรไฟล์สัตว์อ่านรายการที่เผยแพร่จาก CMS แล้ว รองรับเพิ่ม ลบออกจากรายชื่อ ซ่อน เรียงลำดับ เปลี่ยนภาพ และข้อความไทย/อังกฤษ โดยใช้ component เดิม เบอร์หลัก/เบอร์เพิ่มเติมอ่านจาก CMS ทั้งปุ่มโทร ท้ายหน้า และ metadata รวมถึงตารางเวลาเปิดปกติและวันพิเศษ ข้อมูลตัวอย่างยังคงเบอร์ที่ตกลงไว้ทั้งสองเบอร์ การอัปโหลดภาพไม่ผูกหรือเผยแพร่ภาพอัตโนมัติ

แก้ข้อผิดพลาดเดิมใน D1 venue repository ที่ทำให้บันทึก draft ไม่ได้ และป้องกันการเขียน audit ของการแก้ไขที่แพ้การตรวจเวอร์ชัน มี test จำลอง D1 ผ่าน SQLite adapter โดยไม่แตะฐานข้อมูล Cloudflare จริง

รีวิวพบและแก้เพิ่มสามกรณี: รูปสัตว์ที่เผยแพร่แล้วต้องไม่หายเมื่อมีรูปใหม่เกิน 100 รูป, คำสั่งแก้ข่าวที่แพ้การตรวจเวอร์ชันต้องไม่แก้ข้อความ รูป ฉบับเผยแพร่ หรือ audit แม้สองคำสั่งมีเวลาเดียวกัน และ CMS ขัดข้องหรือลบเบอร์หลักต้องไม่ทำให้เบอร์เก่ากลับมาแสดง ทั้งหมดมี regression tests ที่พบอาการก่อนแก้และผ่านหลังแก้

เนื้อหาเมนูเต็ม กิจกรรมแบบแค็ตตาล็อก หน้า events, Zoo Clubs และพาร์ตเนอร์ยังอยู่ในโค้ดตามขอบเขตนี้ ส่วนหลังบ้าน Admin เดิมยังไม่มีฟอร์มรายชื่อสัตว์ แต่ MCP แก้ผ่าน schema เดียวกับข้อมูลร้านได้ ตัวเว็บที่เปิดตาม config ปกติยังใช้ fixture จนกว่าจะตั้งค่า CMS จริง ไม่มีการอ้างว่าต่อ AI ของเจ้าของหรือ production แล้ว

## การตรวจและงานก่อนเปิดจริง

ผลตรวจ: website Astro check 73 ไฟล์ไม่มีข้อผิดพลาด, unit tests 24 เคสผ่าน, browser tests 33 เคสผ่าน และ build ผ่าน ส่วน CMS checks ผ่านทั้ง 8 packages, tests รวม 88 เคสผ่าน และ build ผ่านรวม Admin ทั้ง 4 โปรไฟล์ รวมการเรียก MCP ผ่าน HTTP จริงกับฐานข้อมูลทดสอบแยก ครอบคลุม token ผิด เวอร์ชันเก่า validation ฉบับเผยแพร่ และ audit

ตรวจ actual render 15 ชุด (5 หน้า × desktop/light, mobile/light, mobile/dark) ไม่พบภาพเสียหรือหน้าเว็บล้นแนวนอน ทดสอบ MCP → published API → Astro HTML จริง 11 ข้อ รวมการเพิ่ม/นำสัตว์ออก เปลี่ยนภาพ แก้ข่าว เบอร์ เวลาเปิดปกติ/วันพิเศษ และ CMS ตอบ 503 แล้วไม่คืนเบอร์เก่า คำสั่งจบสำเร็จและปิด process ทดสอบแล้ว ส่วนช่องเบอร์เพิ่มเติมใน Admin ผ่านการพิมพ์ บันทึก ตรวจ payload ว่าเก็บรายชื่อสัตว์เดิม และแสดงข้อความเมื่อเวอร์ชันชนกัน โดยใช้ API จำลองใน browser เพื่อทดสอบ UI

**รีวิวอิสระ: PASS สำหรับงานในเครื่องรอบนี้** ผู้ตรวจตรวจ HEAD ของทั้งสอง repo และ SHA-256 ของ 73 ไฟล์ อ่านอย่างเดียวใน checkout ร่วมโดยไม่ได้รับประวัติการลงมือทำ และรัน regression D1/media กับ contact/SEO ด้วยตัวเอง Root เป็นผู้แก้โค้ดและเก็บหลักฐาน browser interaction ส่วนผู้ตรวจดูภาพต้นฉบับและภาพ render บางชุด ผลนี้ไม่รวม production, Cloudflare จริง หรือ AI client ของเจ้าของ ดู [บันทึกรีวิวและรายการไฟล์ที่ตรึงไว้](review/owner-ready-2026-10-27/README.md)

ยังต้องเตรียม endpoint CMS ที่เข้าถึงได้และทดสอบกับ AI client ที่เจ้าของเลือก (server ปัจจุบันใช้โปรโตคอล `2026-07-28`), นำเนื้อหาและรูปเริ่มต้นเข้าฐานข้อมูล/ที่เก็บรูปจริง เปลี่ยนเว็บเป็นโหมด CMS และตรวจค่าการ deploy จริง ส่วน GTM, Live Cam, โหวต, เกม, ระบบแต้ม/Top Spenders, FARM และ Art Space ยังรอข้อมูลเฉพาะของแต่ละระบบ ไม่มีการเปิดฟีเจอร์จำลองแทน
