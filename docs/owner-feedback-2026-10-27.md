# สิ่งที่ต้องปรับเว็บไซต์ A Cup of Zoo จากบรีฟเจ้าของร้าน

> อัปเดตการลงมือทำ: ผู้ใช้อนุมัติให้แก้ส่วนที่ข้อมูลพร้อมและเลือกใช้ CMS แพลตฟอร์มเดียวกับ Portfolio พร้อม MCP แล้ว ดู [แผนงานปัจจุบัน](superpowers/plans/2026-10-27-owner-ready-content.md) และ [ผลการแก้ไข](owner-ready-changes-2026-10-27.md) ข้อเสนอด้านล่างเก็บไว้เป็นประวัติ บทสรุป “ยังไม่มีหน้า” และสิ่งที่ต้องรอยืนยันให้เทียบสถานะใหม่ก่อนใช้ต่อ

อ่าน [Website Brief_A Cup of Zoo cafe](https://canva.link/w28jcu2fj17qetw) ครบ 11 หน้าเมื่อ 27 ตุลาคม 2026 และเทียบกับ source ปัจจุบันกับ [เว็บไซต์ preview](https://a-cup-of-zoo-preview.a-cup-of-zoo-website.workers.dev/)

**เว็บมีหน้าหลักสองภาษา เมนูอาหาร และข้อมูลแพ็กเกจแล้ว แต่บรีฟรอบนี้เพิ่มทั้งเนื้อหาและระบบใหม่หลายชุด** ข้อมูลที่ได้รับใช้ต่อได้กับเล่มเครื่องดื่ม แผนผังร้าน รูปและชื่อสัตว์ ทัวร์/อีเวนต์ ผลงานโฆษณา พาร์ตเนอร์ และข้อมูลสมาชิก ส่วนโหวต กล้องสด แต้มสมาชิก เกม และการรับบทความจาก AI ต้องกำหนดวิธีทำงานและข้อมูลเชื่อมต่อเพิ่ม

รายการด้านล่างเป็นผลสรุปและข้อเสนอจัดลำดับงาน ยังไม่ได้แก้เว็บไซต์หรือ deploy รอบนี้ การแบ่งรอบเปิดเว็บเป็นข้อเสนอ ไม่ใช่การตัดฟีเจอร์ที่เจ้าของขอออกจากขอบเขต

## ข้อแตกต่างจากแผนเดิม

1. **เมนูลิงก์กับ HTML:** [มติวันที่ 26 กันยายน](menu-import.md) ให้ใช้ native และไม่เรียก Heyzine แต่บรีฟใหม่หน้า 5 ระบุว่าเปิดเป็น Link ได้เลย ข้อความนี้อนุญาตวิธีที่ง่ายขึ้น ไม่ได้ระบุให้ลบ catalog เดิม ข้อเสนอคือคงอาหาร 47 รายการ เพิ่มปุ่มเล่มเครื่องดื่ม และพิจารณาลิงก์เล่มอาหารประกอบ ก่อนเปลี่ยนต้องปรับ acceptance และ tests ที่ห้าม Heyzine ให้ตรงมติใหม่
2. **มีข้อมูลเครื่องดื่มแล้ว:** ได้ PDF 27 หน้าเก็บไว้ ข้อความในบันทึกเก่าว่าไม่มีเล่มเครื่องดื่มเป็นสถานะในอดีต
3. **CMS ยังไม่ครอบคลุมเนื้อหาทั้งเว็บ:** `MenuPage.astro` และ `ActivitiesPage.astro` อ่าน catalog ใน source; `AnimalsPage.astro` มีเนื้อหาและรายชื่อส่วนใหญ่ในโค้ด ต้องเพิ่ม content model หากร้านจะดูแลรายการเหล่านี้เอง
4. **Free Zone มีเงื่อนไข:** ไม่ควรเขียนว่าเข้าฟรีทุกโซน เพราะมีขั้นต่ำในคาเฟ่และแพ็กเกจโซนสัตว์แยกกัน

ลำดับนี้เป็นข้อเสนอ ยังไม่ได้ยืนยันว่าทุกระบบต้องพร้อมวันเปิดหรือทยอยตามมาได้

### รอบแรก เนื้อหาที่พร้อมและทางติดต่อ

1. คงธีมและหน้าหลัก เพิ่มเล่มเครื่องดื่ม แผนผังที่ขยายได้ และโปรไฟล์สัตว์
2. ทำ Group Tour & Events, รับงานโฆษณา/ออกอีเวนต์, Zoo Clubs พร้อมทางสมัคร LINE และ Our Partner เติมรายละเอียดที่ยืนยันแล้ว พร้อม TH/EN
3. เตรียม FARM และ Zoo Art Space เมื่อมีข้อมูลจริง ไม่เปิดหน้าที่มีแต่หัวข้อหรือปุ่มที่ยังใช้งานไม่ได้
4. เตรียมบทความที่พร้อมเผยแพร่และขอบเขตนำเข้าจาก AI เริ่มจากร่างที่เจ้าของตรวจได้หากยังไม่เลือกการเชื่อมอัตโนมัติ

### ก่อนปลด noindex และใช้โดเมนร้าน

- ยืนยันโดเมน production และตั้ง `site` แทน `https://acupofzoo.invalid`
- เตรียม CMS ที่ Cloudflare เข้าถึงได้ กำหนด `CMS_BASE_URL`, `CONTENT_MODE=cms`, `SITE_ENV=production`; โค้ดปัจจุบันปฏิเสธ fixture ใน production
- เตรียม build ที่มี `@lukespace-cms/client` ซึ่งอ้าง `file:../CMS-Platform-acupofzoo/packages/client` หาก deploy จาก Git repo เดี่ยวต้องแก้การจัดส่ง dependency ก่อน
- ให้เจ้าของทดลองแก้ข้อมูล บันทึกร่าง เผยแพร่ แล้วเห็นผลบนเว็บ รวมทุกส่วนที่ตกลงว่าแก้เองได้
- ยืนยันชื่อร้าน ข้อมูลจอดรถ และรายละเอียดบริการที่ยังรอคำตอบใน [business evidence](../reference-data/business-evidence.json); รักษามติเบอร์เดิมเว้นแต่มีคำสั่งใหม่
- ติด GTM หลังมี container และรายการ event ตรวจว่าปุ่มส่ง event ตรงหน้าที่
- ตรวจมือถือและ desktop ทั้งสองภาษา: เมนู แผนผัง ราคา ปุ่มติดต่อ/LINE/นำทาง และกรณีข้อมูลไม่พร้อม
- ตรวจ canonical, hreflang, sitemap, robots, 404 และ metadata บนโดเมนจริง แล้วปลด noindex เฉพาะ production ตามจังหวะเผยแพร่ที่อนุมัติ preview คง noindex

### ระบบที่ต้องกำหนดรายละเอียดก่อนพัฒนา

โหวตและอันดับสัตว์, Live Cam, แต้ม/คูปอง/Top Spenders, เกม และการรับบทความอัตโนมัติจาก AI ยังต้องกำหนดกติกาและระบบต้นทาง หากต้องพร้อมวันเปิด ให้รวมเป็นเงื่อนไขเปิดเว็บด้วย

## ข้อมูลที่ต้องสรุปกับเจ้าของก่อนลงมือรอบถัดไป

1. ฟีเจอร์ใดต้องมีวันเปิด โดยเฉพาะโหวต Live Cam เกม และแต้ม
2. คง HTML พร้อมลิงก์เล่ม หรือใช้ลิงก์เป็นหลัก และเล่มเครื่องดื่มนี้เป็นราคาที่ใช้เปิดเว็บหรือไม่
3. ระบบสมาชิก LINE ลิงก์สมัครจริง วิธีจัดการแต้ม และข้อมูลที่ต้องการให้เว็บแสดง
4. เนื้อหา Group Tour/รับงาน/FARM/Art Space, สิทธิพาร์ตเนอร์ และรูปต้นฉบับที่เลือกใช้
5. โดเมน, GTM container, CMS และข้อมูลที่เจ้าของต้องแก้เอง รวมขอบเขต maintenance

## ขอบเขตการตรวจ

ตรวจภาพย่อครบ 11 หน้า อ่านข้อความจาก Canva viewer ตรวจภาพประกอบสำคัญขนาดจริง และเก็บ PNG ตามความละเอียดที่ viewer ให้มา ไม่ใช่ export ไฟล์ Canva editable หรือภาพสไลด์ความละเอียดเต็ม

เทียบ source ใน working tree ที่มีการแก้ไขค้างก่อนเริ่มงาน กับหน้าแรก เมนู สัตว์ กิจกรรม และข่าวบน preview ผ่าน BrowserOS neo เป็นการเทียบข้อมูลและความต้องการ ไม่ใช่การรับรอง interaction, accessibility หรือ production readiness ทั้งระบบ ไม่ได้แก้ product code รัน application tests ใหม่ หรือเผยแพร่เว็บ
